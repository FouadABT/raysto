# Shared demo domain API

Import `package:raysto/domain/domain.dart`. `DemoStore` is a `ChangeNotifier`; use `await DemoStore.open()` for persisted storage or `DemoStore(persistence: MemoryDemoPersistence())` for deterministic seeded tests. `await store.restore()` restores. `await store.flush()` awaits queued persistence. Public data collections are read-only list views; write through store actions. Actions throw `DomainException(message)` on invalid input or permission.

Enums: `DemoRole {guest, customer, owner, manager, waiter, kitchen, courier}`, `ServiceMode {dineIn, pickup, delivery}`, `OrderStatus {draft, submitted, accepted, preparing, ready, served, collected, delivered, completed, rejected, cancelled}`, `PaymentOutcome {success,pending,failed,cancelled}`, `AttemptStatus {pending,succeeded,failed,cancelled}`, `TableStatus {available,occupied,reserved,needsReset}`, `RequestStatus {sent,acknowledged,completed,cancelled}`, `DeliveryStatus {unassigned,assigned,collected,outForDelivery,delivered,issue}`, `ReservationStatus {confirmed,arrived,seated,cancelled,noShow}`.

Core getters: `currentAccount`, `currentRestaurant`, `settings` (locale, appearance, reducedMotion, haptics, textScale), `now`, `generation`, `online`, `delayMode`, `nextPaymentOutcome`, `accounts`, `restaurants`, `menuItems`, `tables`, `floorObjects`, `visits`, `orders`, `attempts`, `payments`, `refunds`, `requests`, `deliveries`, `reservations`, `waitlist`, `notifications`, `activity`; `restaurantMenu`, `restaurantTables`, `visibleOrders`, `visibleRequests`, `visibleDeliveries`, `visibleReservations`, `visibleNotifications`, `visibleActivity`, `activeVisit`, `cart`.

Identity: accounts have id/email/name/role/restaurantId/active/onboardingStep/onboardingComplete/addresses/preferences/favorites. Seed ids `new-customer`, `customer`, `diner`, `owner`, `manager`, `waiter`, `kitchen`, `courier`, `harbor-owner`, `guest`; restaurant ids `olive`, `harbor`; item ids `olive-bowl`, `olive-wrap`, `olive-lemonade` establish EUR22; table `olive-table-06`, active visit `visit-06`, invitation `RAYSTO-JOIN-06`.

Actions: `switchAccount(String id)`, `selectRestaurant(String id)`, `signIn(email,password)`, `createAccount(name,email,password)`, `completeOnboarding()`, `updateProfile({name,avatar})`, `updateSettings({locale,appearance,reducedMotion,haptics,textScale})`, `setPreference(String,bool)`, `toggleFavorite(String)`, `saveAddress(Address)`, `deleteAddress(String)`, `setDefaultAddress(String)`, `resetPersonal()`, `resetWorld()`, `loadScenario(String letter)`, `advanceTime(Duration)`, `setConnectivity(bool)`, `setPaymentOutcome(PaymentOutcome)`, `setDelayMode(String)`.

Cart: `cart` has accountId/restaurantId/lines/mode/visitId/addressId/pickupSlot/coupon/tipMinor and totals (`subtotalMinor`, `discountMinor`, `deliveryFeeMinor`, `totalMinor`) through `store.cartTotals([Cart?])`; line fields id/itemId/name/unitPriceMinor/quantity/modifiers/note, subtotalMinor. `addToCart(itemId,{quantity=1,Map<String,List<String>> selections=const{},note=''})`, `updateCartLine(lineId,{quantity,note,selections})`, `removeCartLine`, `restoreCartLine`, `clearCart`, `configureCart({mode,visitId,addressId,pickupSlot,tipMinor})`, `applyCoupon(String)`, `reorder(String orderId)`, `referenceBasket()`, `proposeBasket({budgetMinor=2500,vegetarian=true})`, `applyProposal(List<CartLine>)`.

Payments: `beginCheckout({bool payAtEnd=false,String method='Demo PayPal'})` returns CheckoutAttempt, `Future<CheckoutAttempt> simulatePayment(String attemptId)`, `resolvePayment(String attemptId,PaymentOutcome)`, `beginVisitPayment(String visitId,{String method='Demo PayPal'})`, `collectCash(String visitId)`; `refundOrder(String orderId,{String reason='Customer request'})`. Attempts freeze lines/allocations and have id/accountId/restaurantId/visitId/orderId/status/totalMinor/method/createdAt. `visitBalance(String)`, `orderBalance(String)`, `orderPaid(String)`, `visitOrders(String)`, `canCloseVisit(String)`, `report({DateTime? from,DateTime? to})` return derived values; report has salesMinor/capturedMinor/refundedMinor/outstandingMinor/orderCount/averageMinor/channelCounts/topItems.

Orders: id/restaurantId/accountId/visitId/mode/status/lines/totalMinor/createdAt/note/reason; `transitionOrder(id,OrderStatus,{reason=''})`, `completeOrderItem(orderId,lineId,bool)`. `allowedOrderTransitions(Order)` permission-aware. Orders store frozen prices/options. Only succeeded pay-before attempts release submitted orders; pay-at-end releases unpaid orders.

Tables/visits: Table id/restaurantId/label/seats/zone/shape/x/y/width/height/rotation/status/active/assignedStaffId; `tablePayload(String)`, `parseTablePayload(String)` returns DemoTable; `startVisit(tableId,{guests=2})`, `joinVisit(String invitation)`, `moveVisit(visitId,tableId)`, `closeVisit(String)`, `resetTable(String)`, `saveTable(DemoTable)`, `deleteTable(String)`, `saveFloorPlan(List<DemoTable>,List<FloorObject>)`; visits id/restaurantId/tableId/participantIds/guestCount/startedAt/closedAt/invitation/invitationExpiresAt. `requestService(String kind,{String? visitId,String note=''})`, `transitionRequest(id,RequestStatus,{String reason='',String? assigneeId})`.

Operations: `saveMenuItem(MenuItem)`, `duplicateMenuItem(String)`, `archiveMenuItem(String)`, `setAvailability(id,bool)`, `saveRestaurant(Restaurant)`, `createRestaurantDraft(String)`, `publishRestaurant(bool)`, `importSampleMenu()`, `publishImport(List<MenuItem>)`, `setTeamActive(String,bool)`, `assignStaff(String accountId,List<String> tableIds)`, `inviteTeam({required String name,required String email,required DemoRole role})`, `assignDelivery(taskId,courierId)`, `progressDelivery(id,DeliveryStatus,{String note=''})`, `resolveDeliveryIssue(id)`. Restaurant copyWith available with name/description/address/services/open/published/payAtEnd/deliveryFeeMinor/minimumDeliveryMinor/preparationMinutes/hours/plan.

Reservations: `bookReservation({required String restaurantId,required DateTime at,required int guests,String note=''})`, `modifyReservation(id,{DateTime? at,int? guests})`, `cancelReservation(id)`, `arriveReservation(id)`, `seatReservation(id,tableId)`, `joinWaitlist({int guests=2})`, `leaveWaitlist(id)`. `markNotificationRead(id)`, `dismissNotification(id)`, `addSupportMessage(String,{String? orderId})`, `saveReview(orderId,rating,note)`.

Models provide `toJson()` and `copyWith` for editable restaurant/menu/table/address. Add interfaces by coordinated message rather than direct writes from screens.

Additional implemented interfaces:

- `sessionActive` is false for the initial welcome. `switchAccount`, `signIn` and `createAccount` enter a session; `signOut` returns to welcome. `currentAccount` is always non-null (guest while signed out).
- `currentAccount.workspaceIds`, `hasRestaurantAccess(id)` and typed `assignments` preserve an owner's earlier restaurant access when a setup draft is created. `selectRestaurant` validates authorization and updates the selected staff workspace.
- `visibleAttempts` is permission scoped. Use this for route lookup rather than the raw fixture collection. `canAccessVisit(visit)` and `canAccessOrder(order)` support direct-route guards. `simulatePayment` checks permission when started, retains the original associations after role changes, and cancels its timer on global reset or scenario replacement.
- `CheckoutAttempt.deliveryFeeMinor`, `discountMinor`, `tipMinor` and `address` are frozen alongside its cart snapshot. Later restaurant fee/address edits cannot change a pending purchase. Its `totalMinor` is the authoritative frozen total.
- `importDraft`, `saveImportDraft(items)`, `clearImportDraft()` persist restaurant-scoped extraction review drafts. Import publication validates the entire batch before committing it.
- `updateVisit(id,{guests,note})`, `noShowReservation(id)`, `notifyWaitlist(id)` and `seatWaitlist(id,tableId)` support operational details. Reserved tables can be explicitly seated from reservations; ordinary table scans cannot open them.
- `supportMessages` and `reviews` are filtered for the current account. Support records use `text` and `fromSupport`; replies are explicitly local. `setPermission`, `setNotificationPreference`, `updateOnboardingStep`, `replayOnboarding` and `simulateViewDelay` support settings/onboarding.
- Pickup fixture values are `ASAP`, `As soon as possible`, `In 30 minutes`, `In 60 minutes`. Delivery address cities are `Demo Central` or `Central` (case insensitive). Coupon `FRESH10` gives 10%; `EXPIRED` exercises expiry. Customer pickup confirmation is permitted only for their own ready pickup order.
- `resetPersonal` clears the current person's preferences, addresses, favorites, cart drafts, local support and reviews; it preserves historical restaurant records. Global reset replaces all fixture records and cancels old domain operations. All storage is local JSON, schema and fixture version 1.
- `Restaurant.logoAsset` is independent of `cover`; both point to bundled assets. `pickupSlots` and `deliverySlots` are editable lists, defaulting to `ASAP`, `In 30 minutes`, `In 60 minutes`; empty delivery slots block new delivery checkout.
- `parseOpeningHours(hours)` returns typed daily `OpeningInterval` values. Supported input is a daily `HH:MM–HH:MM` interval, comma-separated intervals, and overnight intervals; existing `Every day`/`Mon–Sun` prefixes are accepted. `isRestaurantOpen(restaurant,{at})` combines the manual open switch with those intervals at the controllable demo clock. New ordering, visits, waitlist, reservation slots and reservation edits obey it; old accepted records remain actionable. This intentionally does not model weekday-specific schedules.
- `persistenceError` changes notify listeners after asynchronous save failure/recovery without enqueueing another save. `retryPersistence()` retries the complete current world.

The public raw collections support repository inspection and demo orchestration; feature routes must select the permission-scoped getters. This local prototype is not production authorization or a backend security boundary.
